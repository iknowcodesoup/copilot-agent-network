- (direction) User asked to convert the spec at specs/001-gpu-pipeline-video-scoped-ingestion/README.md into BMAD SPEC kernel format, full fidelity into companions, one spec folder per source document. specs/ is deleted after the user reviews the conversion.
- (note) Source verified against star-trek-voyicer at commit 5b88eae. video_dir_for(character, url) builds work/<character>/youtube/<video_id>/, so videos nest inside character namespaces (main.py:127-140). Re-ingesting the same video for a second character repeats download, transcribe, and diarize. This is the only real blocker.
- (note) Already built, must not be rebuilt: speaker_map.json is already video-scoped and multi-character (review.py:143-185); count_by_speaker returns label-to-clip-count (diarize.py:119-124); JobRequest.character is already str-or-None (api.py:110), the character tie lives only in the path helper.
- (capability) CAP-1 intent: a video ingests once, at work/videos/<video_id>/..., independent of character, so a second character claiming the same video reuses the cached artifacts instead of re-downloading, re-transcribing, and re-diarizing. success: claiming an already-ingested video for a new voice runs no download, transcribe, or diarize step.
- (capability) CAP-2 intent: the control API lists ingested videos and each video's speaker labels with clip counts, independent of any character prefix. success: GET /videos returns ingested video IDs with diarization status; GET /videos/{id}/speakers returns labels and clip counts sourced from count_by_speaker.
- (capability) CAP-3 intent: a single commit can route one or more videos' speaker labels to multiple characters at once. success: committing a payload shaped {video_id: {speaker_label: character}} creates or grows every named character's dataset with clips from every named video in one commit.
- (capability) CAP-4 intent: preprocessing regenerates the training config whenever the dataset has grown since the config was last written, instead of silently skipping. success: running preprocess after new clips land in dataset/ regenerates training/config.json; running it again with no new clips skips.
- (constraint) Breaking change: VoiceFactoryGateway in copilot_agent_network binds to the five character-scoped routes this spec moves (get_clips, update_clips, set_speaker_map, get_training_progress, stream_clip_audio at voice_factory_gateway.py:170-210). The gateway URLs must be updated in the same change or the /api/voice dashboard breaks. Only get_training_progress stays character-scoped.
- (constraint) speaker_map.json's content and readers do not change, only its filesystem path moves with the rest of the video artifacts.
- (constraint) Existing work/<character>/youtube/* directories from before this change need an explicit migration decision: move them to the new layout, or accept a one-time re-ingest in development. Left open, not decided, in the source spec.
- (non-goal) Rebuilding multi-character clip routing is out of scope. commit_reviewed_clips already reads speaker_map.json and routes each speaker's clips to the right character's dataset (review.py:143-185); this spec only moves where that file and its siblings live on disk.
- (non-goal) Changing the JobRequest data model is out of scope. JobRequest.character is already optional; no model change is needed, only the path helper.
- (non-goal) The pythonapi data model split (voices, voice_contributions tables) is out of scope for this spec. It is owned by spec-multi-voice-data-model, which depends on this spec because the gateway URL contract changes here.
- (question) Open: which migration path for existing work/<character>/youtube/* directories - move them programmatically, or accept a one-time re-ingest in development? Needs a human decision before the ingest-path change ships.
