- (direction) User asked to convert the spec at specs/003-frontend-videos-and-voices-views/README.md into BMAD SPEC kernel format, full fidelity into companions.
- (direction) Depends on spec-multi-voice-data-model: this view relies on the assign/commit/train routes and the voices and contributions data that spec introduces.
- (note) Current gaps, from frontend code review: apps/agentic-executor/src/app/page.tsx renders all runs in one flat list (95 lines), no separation between ingestion and voice management.
- (note) features/voices/speaker_board.tsx (lines 31-212) is scoped to one run. Speaker naming is a free-text Input (lines 121-133), not a searchable list of existing voices.
- (note) approve() (lines 93-99) posts the whole speaker map and starts training in one step. No intermediate assign-but-do-not-train state.
- (note) useVoiceRuns() hook returns a flat array. No grouping by voice, no way to see which videos contributed to a voice.
- (capability) CAP-1 intent: a person can navigate between a Videos view (ingestion review) and a Voices view (voice management and training) as two distinct screens, not one flat list. success: a tab or nav segment switches between videos_view.tsx and voices_view.tsx; each renders independently.
- (capability) CAP-2 intent: the Videos view shows every ingestion run with its speaker clips, and lets a person assign a video's detected speakers to a new or existing voice by search instead of free text. success: a table lists video title, source URL, speaker count, and diarization status; expanding a row shows detected speaker clips; naming a speaker uses a combobox that searches existing voices or creates one inline.
- (capability) CAP-3 intent: assigning speakers and committing those assignments are two separate actions a person triggers deliberately, so multiple videos can be reviewed and held before any of them commit. success: Assign speakers opens the combobox without training; Commit assignments locks in assignments and creates contributions; Discard resets a run to AWAITING_REVIEW; multiple videos can be assigned in parallel and committed one at a time or in batch.
- (capability) CAP-4 intent: the Voices view shows every voice as a durable entity with the videos that contributed to it, its training status, and explicit actions to train or download. success: a card grid shows each voice's name, status (AWAITING_COMMIT/TRAINING/EXPORTING/READY/FAILED), total clip count, and model size when READY; each card's contributing-videos popover lists every video, its clip count, and assignment date; a voice with AWAITING_COMMIT contributions shows a Train now banner.
- (constraint) The speaker_board review flow (playing clips, reviewing quality) stays the same. Only the naming action changes (combobox instead of free text) and assignment is separated from training.
- (constraint) Data queries this view depends on: GET /voices (list with phase and checkpoint), GET /voices/{id} (voice plus contributions array), POST /voices (create by name only), GET /runs (ingestion runs only, no training phases) - all from spec-multi-voice-data-model.
- (non-goal) This spec does not change the pythonapi routes or data model themselves; it consumes the assign, commit, and voices routes that spec-multi-voice-data-model defines.
- (non-goal) This spec does not change how clips are reviewed for audio quality; the existing speaker_board playback flow is preserved as-is.
